# Boot preloads `/sprites/terrain/sand_water_overlay.png`, which is not shipped, so the browser acceptance tier fails on a new console error

- **Bug:** `preloadAllSprites()` requests the optional sand-water transition overlay sheet, but `public/sprites/terrain/sand_water_overlay.png` does not exist, so every boot logs `Asset preload failed — continuing with fallbacks / Failed to load sprite: /sprites/terrain/sand_water_overlay.png` and `npm run test:browser` fails on one new console error
- **Status:** resolved — live verification pending
- **Date discovered:** 2026-09-16
- **Version/build:** 0.6.4
- **Reporter:** autonomous build-repair pass (browser acceptance tier, `npm run test:browser`)
- **Area:** UI (presentation / asset preload)
- **Owner module:** `src/game/spriteLoader.ts` (boot preload list); the optional bake lives in `src/game/terrainAtlas.ts` + `src/game/terrainLayer.ts`

## Status history

- 2026-09-16 — open (found by `npm run test:browser`; the preload line dates from 2026-09-13 13:55, after the simulation audit's browser verification, which is why the tier has been failing unnoticed)
- 2026-09-16 — investigating (the sheet is absent from the whole workspace; the atlas already treats it as optional, so the minimal repair is the mountains precedent: stop preloading absent art and keep the defect recorded here. Whether the art is coming or abandoned is the owner's call, exactly as `BUG_REPORTS/2026-09-10-mountain-sprites-missing.md` left it)
- 2026-09-16 — resolved — live verification pending (preload omitted; the error no longer fires and the tier is green. The sheet itself is still missing, so the bake stays on its documented no-overlay path until the art ships; a player-facing look at shore/river-bank edges is still the remaining check)

## Observed behavior

`npm run test:browser` (after `npm run build`) exits 1 with `"verdict": "fail"` and:

```json
"consoleErrors": 1,
"knownConsoleErrors": 0,
"failures": [
  "1 new console error(s): Asset preload failed — continuing with fallbacks Error: Failed to load sprite: /sprites/terrain/sand_water_overlay.png\n    at r.onerror (…/assets/game-ui-*.js:4:76966)"
]
```

Everything else in the run is healthy: WebGL2 present (`ANGLE … D3D11`), the valley paints (5 219 distinct sampled colours), the HUD clock advances on its own (`11:00 → 15:00`), the guided first-spring overlay is dismissed, and there are 0 page exceptions, 0 failed requests and 0 bad responses.

## Expected behavior

Boot requests only art the build actually ships. The overlay is optional by design, so the atlas bakes without it and re-bakes once it appears; a missing sheet must therefore not be preloaded eagerly. The harness's own policy (CHANGELOG, 2026-09-10) is that a missing-asset defect stays visible as its own record (`BUG_REPORTS/`) rather than as a red gate.

## Reproduction steps

1. `npm run build`
2. `npm run test:browser`
3. The run reports exactly one new console error, the missing `/sprites/terrain/sand_water_overlay.png` above, and exits 1.

Static reproduction:

1. `src/game/spriteLoader.ts` — the `preloadAllSprites()` list requested `/sprites/terrain/sand_water_overlay.png`.
2. `public/sprites/terrain/` — contains 10 files (`dirt.png`, `dirt_fill.png`, `forest.png`, `grass_fill.png`, `mountain.jpg`, `sand_fill.png`, `snow.png`, `snow_light.png`, `water_deep_fill.png`, `water_shallow_fill.png`); the overlay sheet is not among them.

## Evidence

- `src/game/terrainAtlas.ts:20` defines `SAND_WATER_OVERLAY_PATH = '/sprites/terrain/sand_water_overlay.png'`, and `terrainAtlas.ts:197-199` gates the bake on `getSprite(SAND_WATER_OVERLAY_PATH) != null` — the sheet is explicitly **optional**.
- `src/game/terrainLayer.ts:524` reads it through `getSprite` only when an overlay was picked, so nothing else loads it.
- `tests/terrainLayer.overlayCache.test.ts` pins the intended contract: while the sheet is absent the terrain cache stays valid, and the moment it becomes ready `terrainLayerNeedsRebuild` returns `true` once, so the atlas re-bakes.
- `ASSET_REGISTER.md:18` lists only the water fills (`water_shallow_fill.png` · `water_deep_fill.png`, generated by `scripts/generate-water-sprites.mjs`); no script generates the overlay sheet.
- `docs/private/terrain-transition-overlay-and-large-cache-2026-08-21.md:3,24` — the transition-overlay sheets are "Design only. No source, asset, package, version, commit, deployment, or release change is authorized by this document", and the sand-water sheet is listed as a priority-1 sheet **to create**.
- `glob **/*{overlay,sand}*` across the workspace finds no overlay art anywhere (only `sand_fill.png`, the design doc, the tests and `renderer/overlay.ts`).
- The same file already documents the pattern for the other unshipped art: "Mountain peak overlays (`MOUNTAIN_SPRITE_PATHS`) are omitted until `public/sprites/mountains/` ships — preloading missing files spams boot errors."

## Root cause

The 2026-09-13 terrain-material-atlas work added an optional overlay sheet to the bake and eagerly added its path to the boot preload list, but the source art does not exist (`docs/private/…2026-08-21.md` authorizes no asset work; `ASSET_REGISTER.md` does not list it). The atlas is written to work without the sheet, so the only user-visible symptom is the boot console error; no bake or draw path depends on it.

## Impact

One console error on every boot (`Asset preload failed — continuing with fallbacks`). The overlay is simply not baked, so shore and river-bank edges keep the base-tile look; the valley still renders normally and nothing else regresses.

## Regression test

`scripts/browser-smoke.mjs` already fails the run on any console error that is not in `KNOWN_CONSOLE_ERRORS`, which is what caught this. No new test was added: the load path is a boot preload and the Node tier has no image decoder, so the harness is the correct guard. `tests/terrainLayer.overlayCache.test.ts` continues to pin the "absent today, re-bake when it appears" contract.

## Invariants checked

The terrain cache contract is unchanged: with the sheet absent `terrainLayerNeedsRebuild` keeps the existing cache valid, and it still requests exactly one replacement bake when the sheet becomes ready. No terrain bake, season wash or river-clarity rule was touched.

## Save/migration impact

None. The sheet is a build-time render asset; no save field, key or migration is involved, and a loaded colony is unaffected.

## Fix

The boot preload no longer requests `SAND_WATER_OVERLAY_PATH`, with the reason and this report recorded beside the list, the way the mountain paths already are. Restoring the overlay is a one-line change once `public/sprites/terrain/sand_water_overlay.png` ships; until then the atlas stays on its no-overlay path instead of logging a failed asset load on every boot.
