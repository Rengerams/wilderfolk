## 2. Findings

### 🔴 CRITICAL — Story/campaign state is not transported through the worker delta or saved

**Files:** `src/game/simBuffers/simDelta.ts`, `src/game/saveSchema.ts`, `src/game/gameTypes.ts` (lines 819, 835, 837)

`SimTickDelta` does **not** include:
- `storyFlags`
- `pendingStoryEvents`
- `guidedCampaign`

`WORLD_STATE_SAVE_KEYS` (save allow-list) also does **not** include any of those three fields.

Consequences:
1. **Worker mode (the default when `GameWorkerHost` boots successfully):** the main-thread display world only receives `SimTickDelta`s. Story cards are rendered from `world.pendingStoryEvents`, animal-care/election-promise/children-shelter state is read from `world.storyFlags`, and the Campaign panel reads `world.guidedCampaign`. None of those are ever copied from the worker's authoritative world, so the v0.6.3 headline features (S1–S5 authored stories, C1 Guided Campaign, E1 election promises, A1 animal care, children-shelter quest) will be invisible or non-interactive in the real worker-based game. The worker can still mutate its own copies, but the UI can neither display nor act on them.
2. **Save/load (even in main-thread fallback):** `pickWorldFieldsForSave()` drops `storyFlags`, `pendingStoryEvents`, and `guidedCampaign`, so all story/campaign progress is lost on reload.

Evidence: `extractSimTickDelta`/`applySimTickDelta` have no mention of these fields; `gameWorkerHost.ts` applies command/tick deltas to the main-thread `worldRef`; `saveSchema.ts` allow-list omits them; `initGame` does not even initialize `storyFlags`/`pendingStoryEvents` (only `guidedCampaign`).

**Recommendation:** Add the three fields to `SimTickDelta` (extract + apply), to `WORLD_STATE_SAVE_KEYS`, and add a focused regression test that ticks a world far enough to generate a story card and verifies it survives a delta round-trip and a save/load round-trip.

### 🟠 HIGH — Unaffordable story choices consume the card for Deer Parliament, Wedding Diplomacy, and Traveling Theatre

**Files:** `src/game/storyEvents.ts` (`respondToStoryEvent`, lines 166–233), `src/game/deerParliament.ts`, `src/game/weddingDiplomacy.ts`, `src/game/travelingTheatre.ts`

`respondToStoryEvent` removes the event from `pendingStoryEvents` **before** dispatching to the resolver. Only `children_shelter` and `invention_fair` re-add the event when the resolver returns `false`. The other new stories ignore the boolean return, so a resource-gated choice clicked without enough resources:

- **Deer Parliament** (`preserve` needs 40 wood, `symbolic_treaty` needs 20 food): event is consumed, no flags are written, and `FLAG_OFFERED` is already set → the story is permanently lost.
- **Wedding Diplomacy** (stage 1 gifts/envoy, stage 2 feast/delegation): event is consumed while status stays `offered`/`gift_sent` → the story stalls permanently.
- **Traveling Theatre** (stage 2 support packages): stage-2 card is consumed; the story continues to stage 3 automatically, but the player loses the choice.

The story card buttons in `App.tsx` (lines 1735–1748) are **not preflighted/disabled** for resource costs, so this is reachable through the UI.

**Reproduction (Deer Parliament, seed 42, day 200, `wood=0`, click `preserve`):**
```
before: pendingStoryEvents=1
after:  pendingStoryEvents=0, storyFlags.deer_parliament_resolved=0,
        storyFlags.deer_parliament_followup_day=0, wood unchanged
```

**Recommendation:** In `respondToStoryEvent`, treat a `false` return the same way as `children_shelter`/`invention_fair` (re-add the event), or preflight/disable unaffordable choices in the UI. Add regression tests for insufficient-resource clicks on every new story.

### 🟠 MEDIUM — A1 animal-care status machine never reaches “shortage” and does not re-warn after recovery

**File:** `src/game/animalCare.ts`

- `FLAG_SHORTAGE_DAY` is defined (line 15) but **never written**, so the `shortage` branch (line 71) is unreachable. Status can only ever be `fed` or `warning`.
- `FLAG_WARNING_DAY` is never cleared when animals are fed again. After the first warning and a later recovery, the next food-less day falls through both branches and leaves status as `fed` — the animals silently stay un-fed with no warning.

**Reproduction:**
```
day10 food=0 -> warning
day11 food=0 -> warning
day12 food=0 -> warning   (should escalate to shortage)
day13 food=10 -> fed
day14 food=0 -> fed        (should warn again)
```

Existing `tests/animalCare.test.ts` only asserts the first warning; it does not cover shortage escalation or warning re-entry after recovery.

**Recommendation:** Write `FLAG_SHORTAGE_DAY` on the first shortage day, clear `FLAG_WARNING_DAY`/`FLAG_SHORTAGE_DAY` on a successful feed, and add tests for fed → warning → shortage → fed → warning.

### 🟡 MEDIUM — A* pathfinding allocates full-map arrays on Huge maps

**File:** `src/game/pathfinding.ts` (`findPath`, lines 171–172)

`findPath` allocates `Float64Array(cols * rows)` (~8 bytes/tile) and `Int32Array(cols * rows)` (~4 bytes/tile) before the `maxNodes` cap is applied. On the new **Huge 2560×1920 map (~4.9M tiles)** this is ~59 MB per A* call even though the search stops after 6,000 nodes. The path cache is bounded (200 entries), but a wall/water layout that triggers frequent A* calls could cause significant GC pressure.

**Recommendation:** Use sparse maps (`Map<number, number>`) or a fixed-size arena for `gScore`/`came`, or at least allocate based on the search region rather than the whole map.

## 5. Recommendations (priority order)

1. **Add `storyFlags`, `pendingStoryEvents`, `guidedCampaign` to `SimTickDelta` and `WORLD_STATE_SAVE_KEYS`.** Add delta round-trip + save/load regression tests. This is the single highest-impact fix for v0.6.3.
2. **Fix `respondToStoryEvent` to re-add the event when the resolver returns `false`** (or preflight/disable unaffordable choices in the story card UI). Add tests for insufficient-resource clicks on Deer Parliament, Wedding Diplomacy, and Traveling Theatre.
3. **Fix `animalCare.ts` state machine** (write `FLAG_SHORTAGE_DAY`, clear warning/shortage days on feed) and extend `animalCare.test.ts`.
4. **Make A* memory usage map-size-aware** or switch to sparse structures before shipping Huge maps.
5. **Update the changelog** with current test counts (88/474), current jscpd count (1), and correct/remove the reference to `tests/familyReferenceCleanup.test.ts` (or add that test).
6. **Reconcile dependency-cycle tooling** with TypeScript 7 (or use the production build's chunk topology as the cycle signal until dependency-cruiser supports TS 7).
7. **Replace `__dirname` with `import.meta.dirname`** in `vite.config.ts` to silence the future native-config warning.
8. **Deduplicate RNG helpers** between `simRng.ts` and `storyHelpers.ts`.

## 6. Summary

The v0.6.3 branch is in good overall health: **88 files / 474 tests pass**, type-aware lint is clean, the production build succeeds, determinism and worker transport are genuinely proven by tests, and most simulation/balance/map changes are correctly wired. However, the headline **story/campaign features are not integrated with the worker delta or save layer** (critical), and there are two confirmed runtime bugs (story-card consumption on unaffordable choices, animal-care status machine) plus a Huge-map pathfinding memory concern. These should be fixed before 0.6.3 is considered release-ready.
