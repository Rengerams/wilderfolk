# Wilderfolk — Godot Port Roadmap

**Goal:** the Godot 4.7.2 / GDScript build reproduces the TypeScript game's **simulation** exactly, and replaces
its **presentation** with Godot's own.

That split is the whole strategy. Rules are parity-locked; terrain, rendering, UI and audio are free.

## 2. The method: snapshot the state, not the terrain

1. **Snapshot `WorldState` from TypeScript *after* worldgen** and write it as JSON.
2. Feed that same state into the GDScript simulation.
3. Run N ticks and compare the resulting state.

This is what makes phase 5 free while phases 1–4 stay strict: parity then tests **the rules**, never the terrain.
Without it, every terrain difference would look like a simulation difference and the parity signal would drown.

**`WorldState` itself is 1 241 lines** (`gameTypes.ts`) and needs porting in phase 3, because the save format is
its shape. Treat it as the type contract, not as a file to transliterate.

## 4. Why phase 2 comes before more rules

This port exists because of a specific failure in the oracle's repository, and phase 2 is the antidote.

The TypeScript project has an invariant collector, a testing bot and 1495 passing tests — and runs **one** of
them automatically. Its strongest gate was run by hand every few days, so regressions were found late and
"changes that did not resolve" accumulated. The port carries exactly one non-negotiable consequence:

> **The parity suite is the gate. It runs on every change to simulation rules, and it is not something a human
> remembers to invoke.**

Practical form: when you port a rule, port its **test in the same change**. A rule without a parity test is
unverified however carefully it was written, and the invariant collector is what turns a silent divergence into
a failing assertion.

## 5. Current verified state

```
src/game/sim_rng_core.gd              SimRngCore — bit-exact unsigned 32-bit math
src/game/sim_rng.gd                   SimRng — owner streams, snapshot/restore
tests/test_sim_rng.gd                 suite sim_rng — 10 tests / 386 assertions / 0 failed
tests/fixtures/sim_rng_golden.json    golden values, MUST be UTF-8
```

The fixture is generated by the oracle, never by hand:

```powershell
cd C:\Wilderfolk ; npx tsx scripts/dump-sim-rng.mts
```

It writes `C:\Wilderfolk2\tests\fixtures\sim_rng_golden.json` directly as UTF-8. **Never** generate a fixture
with shell redirection: PowerShell 5.1 `>` writes UTF-16LE and Godot's `FileAccess` cannot parse it. That
already cost a cycle once.

## 6. Definition of done

The port is done when a save produced by the TypeScript build loads in the Godot build, the same seed produces
the same world history tick for tick, `simulationInvariants` reports zero violations over a 360-day run, and the
presentation is Godot's own.

## 7. Hazards

All of them have already caused a real failure, and they live in **[`AGENTS.md`](AGENTS.md) §6** — read that
section before writing your first line of GDScript. The short version: JavaScript is 32-bit and GDScript's `int`
is signed 64-bit; Godot's JSON parser returns every number as a `float`; fixtures must be UTF-8; and verify the
shell before trusting PowerShell 7 syntax.

## 8. How to work

[`ARCHITECTURE.md`](ARCHITECTURE.md) decides **what is allowed to change** — the sacred simulation, the seam
that keeps it apart from the free half, and how terrain and rendering may be rewritten.
[`AGENTS.md`](AGENTS.md) is the protocol — parity rules, GDScript over C#, the MCP workflow, the report format.
[`MCP.md`](MCP.md) is the tool reference: what the Godot AI server can do and how to drive it.

The mantra: **read the oracle → port the rule *and its test* → run the parity suite → report.**
